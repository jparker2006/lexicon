- A waiting Dictation's late text is not typed, even when InsertGuard would pass: the spec says late text waits for paste-last.

## Merge Danger

**Door:** two-way. No migration. The only write recovery adds is what the status rules already allow.

**Blast Radius:** History

- Nothing calls `conductor.recover()` in the app yet: `LexiconSystem.run` is #56's stub, which should call it after the tap is live, then `sweepAudio`.
- A kill in the few ms after fn-down, before the writer creates the CAF and History commits the row, leaves neither (under the 0.1 s bound; seen once). The fix is a synchronous file create in `recorder.start` (#43's code).
- The cutoff is wall-clock: a clock jumping backward across a restart defers an earlier run's row to a later launch (not lost; shows recording, can't be deleted meanwhile). A per-run token column would end it.
- Waiting clips that are partly in RAM stay in RAM until text. One 30 s timer per waiting Dictation. A failed SQLite read or dropped write can stall one until the next launch, which finishes it.
- `CAFFile.finalize` throws on a file with no edit count yet: that Dictation lands failed (no audio), the finalize logged each launch.
- Merge order: either way with #53 (PR #123); the Conductor files auto-merge, and `UsageTests.swift` conflicts only where each un-disables its own test (keep both). #119 merges cleanly. #56 builds on `recover()`.
